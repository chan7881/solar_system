# 태양계

COSMIC TRAIL(다른 선생님 작품)의 **태양계 부분만** 떼어 새로 구현하는 3D 웹앱. 수업용(학생이 직접 조작).
원본 분석과 범위는 `원본분석.md`. 원본 사본은 `참고/`(git 제외, 참고용 — 코드·그림을 옮기지 않는다).

## 지금 상태

완료·화면 승인된 것(전부 2026-11-21~22). 수치 대조는 각 테스트와 `textures/출처.md`에 있다. 테스트 526개 통과(`npm test`).

- **틀:** 실제 비율 화면 · 행성 8 · 시간 조작(가운데 = 실제 빠르기, 1800~2050) · 이름표 · 날아가기 · 왼쪽 사이드바(태양계 전체·태양·행성+위성 아코디언·기타) · 오른쪽 아래 레이어 창(톱니) · 별자리(처음엔 꺼짐, 별은 안 그림) · 「전체 보기」.
- **자세:** 전 천체 IAU 2015 + 계별 주기 항(달 E1~E13, 화성계 M, 목성계 J, 토성계 S, 천왕성계 U, 트리톤 N7). 모두 Horizons 태양 직하점과 대조하는 테스트가 있다(`tests/*_rot.test.mjs`, 변이 검사 통과). 히페리온만 혼돈 자전이라 **보기용 회전**(사용자 결정).
- **지도·모양:** 수성·지구·화성·목성·달(NASA CGI Moon Kit)·금성(Magellan, 「대기 끄기」)·타이탄(Cassini 근적외선, 「대기 끄기」)·토성 띠·갈릴레이 4·토성 위성 6·세레스·트리톤·천왕성 위성 5·명왕성·카론. 모양 파일은 포보스·데이모스·히페리온(`textures/*_shape.bin`)·혜성 핵 5. 천왕성·해왕성(띠만)·태양 표면은 단색. 위도·경도 규약 함정은 아래 「함정」.
- **토성 고리:** Cassini 전파 엄폐 광학 깊이로 비침·밝기·토성 그림자·고리 그림자. 셰이더 식은 `src/rings_glsl.js` 한 곳, `tests/rings_glsl.test.mjs`가 JS로 옮겨 `rings.js`와 대조(변이 18개 실패).
- **위성 22개:** 달은 ELP 주요 항, 나머지는 Horizons 1800~2050에 맞춘 식(`tools/fit_moons.py` → `src/moon_fits.js`). 히페리온은 타이탄 4:3 공명 때문에 K 항을 직접 투영으로 15개 찾음(`DIRECT_K`). 행성 중심은 계 질량중심에서 위성 질량만큼 옮김. 궤도선은 고정 격자 시각 점 재사용.
- **소천체:** 왜행성 5·혜성 5(Horizons 접촉 요소 1년 간격) · 점 무리 5종(소행성대·힐다·트로이·카이퍼대·오르트 — 공명 무리는 목성 평균 운동으로 돌림) · 무리 이름표(`groupAnchors`).
- **혜성:** 핵 모양(67P·핼리는 실제 모형, 나머지 근사), 활동량(물 승화 곡선 × 관측 생산율), 이온·먼지 꼬리·코마(`src/comets.js`).
- **도구:** 오른쪽 아래 「도구」 단추 하나 → 목록(거리 재기·크기 비교·궤도 보기) · 거리 재기(km·AU·빛 시간, 선 가운데 글자) · 크기 비교(따로 둔 직교 장면) · 최소·최대 거리와 「그때 위치」(웹 워커 `extremes_worker.js`, 짝마다 기억).
- **궤도 보기(2026-11-22, 화면 승인 2026-11-22):** 그 시각의 요소로 타원·장반경·단반경(중심에서)·근점·원점(km·AU). 행성 Standish · 위성 맞춘 식(달은 ELP 위치·속도의 접촉 요소, μ=지구+달) · 왜행성·혜성 Horizons 요소 보간. 카메라는 중심 천체로 날아가 궤도면에 수직(황도 북쪽 편 — 역행은 시계 방향), 근점 왼쪽·장축 가로, 타원 중심을 카드 밖 빈 곳 가운데에(`controls.target`·`camera.up`을 날아가기에서 옮기고, 다른 곳으로 가면 원래대로). 이름: 태양 둘레 근일점·원일점, 지구 둘레 근지점·원지점, 그 밖 근점·원점. Horizons 대조·변이 15개 실패(`tests/orbit.test.mjs`).
- **지구 밤 불빛·대기(2026-11-22, 화면 승인 2026-11-22):** NASA Black Marble 2016에서 불빛 세기만 뽑은 질감(`tools/make_nightlights.py`)을 밤 쪽에만 — 태양 고도 0°→−12°에서 서서히 켜짐. 가장자리 빛은 지구+100km 껍질(`atmoMesh`), 낮 쪽만. 식은 `src/atmosphere.js` 한 곳(GLSL 문자열 포함), `tests/atmosphere.test.mjs`가 Horizons 직하점으로 도시 5곳 태양 고도 대조·GLSL과 JS 대조(변이 9개 실패). 「대기」 스위치는 지구에도(끄면 가장자리 빛만), 레이어 창에 「지구 밤 불빛」.
- **태양 렌즈 효과(2026-11-22, 화면 승인 2026-11-22):** 본 장면 위 화면 겹침(가산). 후광 4겹(`BLOOM`: 원반 반지름 비례 + 화면 높이 비례, 원반이 크면 35%까지 약하게 — `bloomNearDim`) · 넘친 핵·렌즈 유령 8개(태양–광학 중심 직선 위)·베일(원반이 크면 끔). 가림은 몸체 타원체에 태양 원반 표본 37점으로 선분을 쏘아 비율을 냄(지구 가장자리 뒤에서 서서히 떠오름). 세기는 노출처럼 1/거리²의 로그. **회절 광선은 쓰지 않음(사용자 결정).** **번짐·핵 크기 상한(2026-11-22, 시안 검토 중):** 원반이 점일 때만 화면 높이 몫이 온전하고 5px(/1000px) 이상이면 0.3배까지 줄여 실제 각크기가 우선(`glowShrink`·`coreSigma`). 베일(보라 안개)은 그대로. 식 `src/flare.js`, `tests/flare.test.mjs`(15개, 변이 검사 통과), 레이어 창 「태양 렌즈 효과」. 도구 화면에서는 안 그린다.
- **햇빛 노출(2026-11-22, 시안 검토 중):** 몸체 밝기가 거리와 무관했던 것(PointLight decay 0)을 1/r²로. 초점 천체는 늘 예전 밝기(자동 노출), 다른 천체는 초점 대비 (d초점/d)²을 0.1~2.5배로 잘라 가시성 확보(`src/exposure.js`, 몸체별 `uExpo` — 재질 직접광·토성 고리·지구 구름·가장자리 빛에 곱함, 크기 비교 도구에선 1). `tests/exposure.test.mjs`(변이 검사 통과). 화면 확인은 지구·토성·태양 초점, 1AU·30AU 태양까지 — 행성 여러 개가 한 화면에 든 장면은 아직 안 봄.
- **깊이 오류 수정:** 혜성 꼬리·코마는 깊이 버퍼를 단 꼬리 화면에 몸체(`OCCLUDE` 층)를 깊이로만 먼저 그려 가림 판정, 고리는 궤도선 다음에(`renderOrder` 2.5). **남은 한계:** 고리는 혜성 꼬리를 가리지 않는다(반투명이라 깊이 패스에서 뺌).

## 남은 일

1번만 최우선이고 나머지 순서는 우선순위가 아니다. 기능 항목은 시안·계획을 승인받은 뒤 진행한다.

**이어서 할 때:** 렌즈 효과까지 커밋됨(2026-11-22). **최우선은 1번(지구 구름).** 그 밖 후보는 2·3번 — 고르면 시안·계획부터.

### 1. 지구 구름 (최우선 — 2026-11-22 사용자 지정)

지구에 대기 가장자리 빛과 밤 불빛은 넣었는데 **구름이 빠져 있어 어색하다.** 다른 항목보다 먼저 한다. 기능 항목이라 시안·계획을 승인받은 뒤 진행한다.

- 지금: 지구 표면 지도는 구름 없는 맑은 지도다. 「대기」 스위치는 가장자리 빛만 켜고 끈다(`src/atmosphere.js`).
- **결정(2026-11-22 사용자):** 구름 모습은 Windy 「구름」 레이어를 전반적으로 보고 맞춘다(`windy.com/ko/-구름-clouds?clouds`, 좌표는 무시). 구름은 지표보다 약간 높은 **별도 껍질**로 겹치고, **「대기」 스위치와 같이 켜고 끈다**(별도 레이어 항목 없음). **밤 불빛 위를 덮는** 형식 — 투명도를 조정해 구름 아래의 불빛이 비쳐 보이게 한다. **시간을 돌려도 구름은 고정**(움직이지 않는다).
- **자료 출처(결정 2026-11-22):** Windy는 **모습 기준으로만** 본다 — 약관(`account.windy.com/agreements/windy-terms-of-use` 4.6·2.3)이 대량 내려받기·자동 수집·복사·재배포를 막아 질감으로 쓰지 않는다. 질감은 **NASA GIBS** VIIRS(NOAA-20 + 틈은 NOAA-21) 가시광 합성에서 `tools/make_clouds.py`로 뽑은 투명도(`textures/earth_clouds_4k.jpg`, 흑백 4096×2048, 약 3MB). 눈·얼음은 7-2-1 합성(하늘색)으로 걸러 냄. MODIS는 궤도 가장자리 줄무늬가 커서 버렸고 SNPP는 GIBS가 영상을 주지 않는다.
- **그림자 검토(사용자 요청):** 미리 계산해 붙이는 방식이 된다. 구름 높이 10km의 그림자는 낮은 태양에서도 4K 지도 한두 칸만 밀려서, 따로 굽는 질감·광선 계산 없이 **같은 구름 지도를 지표 바로 아래에 흐리게(mip 편향 1.5) 한 번 더 읽어 어둡게 하는 것**으로 충분하다(추가 질감 0개, 지표 셰이더에 읽기 1회). 세기 `uShadow` 0.4.
- **진행(2026-11-22, 커밋 전 · 시안 검토 중):** `main.js`에 구름 껍질(`cloudMesh`, 지표 +10km, 낮 밝기·박명 붉은 빛·밤은 거의 검게, 불투명도 `uCloudOpacity` 0.92)·그림자를 넣었다. 「대기」 스위치와 같이 켜고 끈다(`updateEarthAtmo`), 레이어 항목 없음, 시간을 돌려도 고정. 밤 불빛 위는 껍질이 불투명도만큼 덮는다. 시안 장면은 scratchpad `earthview.js`(`__ev(mode, 거리km, fov, yaw)`)·`shots_earth2.ps1`.
- **다음:** 시안 승인 → 테스트(질감 로딩·대기 스위치 연동은 자동 확인 어려움 — 화면 확인) → 투명도·그림자 세기 조정 여부 → code-review → 커밋.
- 남은 정할 것: 구름 투명도(밤 불빛이 얼마나 비칠지)·구름이 너무 많이 덮여 보이는지(평균 투명도 0.29)·북극권 이음매.
- 확인: 화면 시안(ISS 높이·지구 전체·낮밤 경계)을 먼저 보이고, 구름 켬/끔 비교.

## 결정된 것

- 원본 코드·그림을 복사하지 않는다 — 다른 선생님 작품이라서. 수치·그림은 1차 출처(JPL·NASA)에서.
- **크기·거리는 늘 실제 비율** — 「보기 좋은 크기」 모드를 두지 않는다(Eyes 방식, 2026-11-21 사용자 결정). 작은 천체는 이름표·동그라미로 찾는다.
- **별 배경은 넣지 않는다**(2026-11-21 사용자 결정).
- **딸린 활동(퀴즈·몸무게 계산 등)은 넣지 않는다** — 태양계의 모습을 보이는 시뮬레이션에만 집중(2026-11-21 사용자 결정).

## 함정

- **IAU 북극 ≠ 자전 벡터.** IAU 북극은 불변면 북쪽에 있는 극이라 금성·천왕성은 자전 벡터(오른손)와 반대다. 자전축 기울기(천왕성 97.8°)는 자전 벡터로 잰다.
- Horizons 직하점은 **측지 위도**이고 경도는 순행 천체가 서경+(타이탄도), 금성·지구·천왕성·달은 동경+ — 받은 파일 머리글의 `{West-longitude positive}`를 본다. 태양에서 보면 광행시만큼 앞선 행성이다.
- 지도는 **가운데 = 경도 0°, 동쪽이 오른쪽**이어야 그대로 맞는다. **USGS 라벨의 경도 방향·가운데 경도를 믿지 말고 지형으로 확인한다**(타이탄 라벨은 서경+·가운데 180°인데 실제 배치는 왼쪽 끝 0°·동쪽이 오른쪽 · 명왕성 300m 모자이크는 태그가 가운데 0°인데 실제는 가운데 180°). 목성 PIA07782는 축 눈금이 서경(180…0…330…180)이지만 배치는 같다. 다른 규약의 원본은 `make_textures.py`에서 돌려 맞춘다.
- 구의 방향: SphereGeometry는 u=0.5가 +X, u가 커지면 −Z 쪽이다 → +X=경도 0°, −Z=동경 90°, +Y=북극(three.js로 확인함).

- 먼 천체는 투영한 z가 반올림돼 정확히 1이 된다 → 「카메라 앞인가」를 `z < 1`로 보면 이름표가 다 사라진다. 카메라 좌표의 z 부호로 본다.
- 고리 τ 질감을 GPU 자동 밉맵에 맡기면 안 된다 — τ를 그대로 평균해 간극이 메워지고, R16F는 모바일에서 자동 생성이 실패해 고리가 조용히 사라질 수 있다. 투과율로 평균한 단계를 CPU에서 넣는다.
- **JPL 위성 평균 궤도 요소표(sats/elem)는 쓰지 마라** — 주기 자릿수가 모자라고 공명 흔들림(미마스 ±43°, 70.7년)이 없어 수십 년이면 수십° 틀린다. 궤도면이 도는 주기가 자료 기간(250년)보다 긴 위성(트리톤·타이탄·이아페투스·칼리스토)은 FFT로 안 잡혀 `fit_complex`에서 낮은 주파수를 직접 훑는다.
- Horizons 트리톤 자료는 1800-01-02부터, 카론(명왕성 중심)은 01-04부터다(`fetch_moons.py` 첫 구간을 늦춤). `fit_moons.py` 전체가 약 37분 걸린다.
- **Horizons의 3축 타원체 천체(포보스·데이모스) 위도**는 「중심 방향 광선이 3축 타원체와 만나는 점의, 회전 타원체(a,a,c) 기준 측지 위도(고도 포함)」다 — 경도는 중심 경도 그대로. 납작해서 반복 계산이 천천히 모인다(30번이면 0.0008° 남음). 화성 중심에서 본 값에는 화성 공전 속도의 광행차(약 0.005°)가 들어 있다.
- **지구-화성 최소 거리는 앱 안에서 2003년이 아니라 1924년이 나온다** — Standish 요소로 2003-08-27이 5,580만km(Horizons 5,576만km, 약 3.8만km 큼)라 1924-08-22(5,576만km)가 근소하게 앞선다. 계산 방법이 아니라 행성 위치 정밀도 문제.
- 해왕성은 Standish 오차가 공표값(10″)보다 크게 나온다(실측 최대 45″). 테스트 허용치는 실측의 약 2배.
- **공명 소천체(트로이·힐다)를 접촉 궤도 요소의 평균 운동으로 돌리면 수십 년 만에 무리가 흩어진다** — 접촉 a가 공명 둘레로 흔들려 평균 운동이 최대 7~9% 다르다. 목성 평균 운동(트로이 1배·힐다 3/2배)으로 돌린다.
- Horizons 혜성은 `DES=1P; CAP;`처럼 지금에 가장 가까운 궤도 해를 고른다. 이 해로 1800~2050년을 적분한 요소를 쓴다(핼리 1835·1910 근일점도 0.11° 안).
