# 태양계

COSMIC TRAIL(다른 선생님 작품)의 **태양계 부분만** 떼어 새로 구현하는 3D 웹앱. 수업용(학생이 직접 조작).
원본 분석과 범위는 `원본분석.md`. 원본 사본은 `참고/`(git 제외, 참고용 — 코드·그림을 옮기지 않는다).

사이드바·시간 조작부(2026-11-21) — 왼쪽 사이드바에 태양계 전체·태양·행성(누르면 위성 아코디언)·기타(행성·위성 아닌 천체가 생기면). 넓은 화면(760px 이상)은 무대를 밀어내고, 폰은 위에 덮는다(고르거나 바깥을 누르면 닫힘). 시간은 Eyes처럼 가운데 = 실제 빠르기(초록 눈금), 왼쪽 과거로·오른쪽 미래로, 멈춤·한 칸씩 단추·실시간. 날짜는 왼쪽 위 날짜를 눌러 고른다. 범위(1800~2050) 끝에 닿으면 「멈춤 · 1800~2050년 끝」.
포보스·데이모스 모양·자세(2026-11-21) — 모양은 Mars Express DSK(포보스 DLR HRSC · 데이모스 Thomas Viking)를 `tools/make_shapes.py`로 방향 10242개에 다시 뽑아 `textures/*_shape.bin`(부피 차 −0.07%, 화면에서 스티크니 확인). 자세는 IAU 2015 + 화성계 주기 항 M1~M10(포보스 W의 d² 항 포함). Horizons 위치로 잰 태양 직하점이 0.00002° 안(`tests/marsmoons_rot.test.mjs`, M5 항을 0.01°만 틀어도 5개 실패), 앱 위치로 재면 0.22°(위치 맞춤 오차).
소천체(2026-11-21, 화면 승인 2026-11-22) — 왜행성 5(세레스·명왕성·하우메아·마케마케·에리스)·혜성 5(핼리·엔케·67P·스위프트-터틀·헤일-밥)는 이름표·궤도선·날아가기 되는 천체. 위치는 Horizons 접촉 궤도 요소 1년 간격을 앞뒤 두 기원에서 옮겨 섞음 — Horizons와 8개 날짜에서 왜행성 0.005°·혜성 0.11°(핼리 1835 근일점) 안. 점 무리는 소행성대 19,539·힐다 454·트로이 4,511(H<14, 거의 다 발견된 크기라 밀도가 실제와 같음)·카이퍼대 4,297(알려진 TNO 중 궤도 확정, 명왕성족 39AU·고전대 42~47AU·48AU 절벽이 자료에 보임)·오르트 구름 30,000(모형: 3,000~100,000AU, 밀도 r^−3.5, 고른 방향). 트로이·힐다는 목성 공명 평균 운동으로 돌려 1800년에도 무리 모양 유지(케플러 평균 운동으로 바꾸면 테스트 실패). 사이드바에 왜행성·혜성·소천체 무리(소행성대·트로이군 / 카이퍼대 / 오르트 구름 보기). 점은 초점 천체에 바짝 다가가면 감춘다.
레이어 창(2026-11-22, 화면 승인) — 오른쪽 아래 톱니 → 오른쪽 창(넓은 화면은 밀어내기, 폰은 덮기). 사용자 화면·행성·왜행성·혜성·소행성대·트로이군·카이퍼대·오르트 구름·무리별 색 구분(스위치, 처음엔 꺼짐 = 흰 점)·궤적(흐려지는 꼬리)·궤도(한 바퀴 고른 선)·이름표·아이콘·별자리(처음엔 꺼짐, d3-celestial 선·한국어 이름 — 별은 안 그림). 레이어를 꺼도 보고 있는 천체와 그 계는 남는다(`nav.js bodyShown`). 점은 반투명(0.32), 궤도선은 점 위에 그린다. 대기 단추는 켬/끔 스위치로. 왼쪽 사이드바 맨 위 「전체 보기」 — 태양계 전체·소행성대·카이퍼대·오르트 구름(모두 태양 중심·같은 기울기, 거리만 다름 · 꺼 둔 무리면 켜고 간다).
무리 이름표(2026-11-22) — 소행성대·힐다·트로이군(L4·L5 따로)·카이퍼대·오르트 구름. 누를 수 없는 이름, 색 구분을 켜면 무리 색. 트로이·힐다는 그 쪽 점들의 평균 방향·거리(`groupAnchors`, 목성 앞 60°·뒤 60°·반대편을 시험 — 부호를 뒤집으면 실패), 고리는 화면 아래(밖이면 위) 가장자리. 태양에서 화면으로 50~110px 넘게 떨어져야, 천체 이름과 안 겹치고 화면에 다 들어와야 보인다.
명왕성·카론(2026-11-22, 승인·검토 반영) — 명왕성 지도는 NASA 색 지도, 카론은 USGS 흑백(`tools/make_pluto.py`, 남쪽 약 1/3 미관측은 평균 색 — 경계는 가까운 관측 색에서 평균 색으로 이어 어두운 띠 없음: 경계 1~3화소 밝기 66→107, 먼 곳 118). 명왕성 USGS 좌표 태그는 틀려 반 바퀴 돌림(Burney 분지로 확인), 카론은 태그대로(Kubrick Mons). 명왕성 위치는 계 질량중심(Horizons `9`) 요소 + 카론 질량 보정(약 2,100km, Horizons와 10km 안). 카론은 Horizons에 맞춘 식(따로 둔 자료 최대 0.004°), 자세는 IAU 2015 — 태양 직하점 0.00001°·마주 보는 점 0.0027°(`tests/pluto_rot.test.mjs`, W·극을 0.05° 틀면 5개 실패, 보정을 빼거나 뒤집으면 1개 실패). 테스트 293개 통과.
도구(2026-11-22, 화면 승인) — 오른쪽 아래 「거리 재기」「크기 비교」. 처음 두 천체는 지구·보는 천체(지구를 보면 달), 목록으로 바꾼다. 거리 재기는 두 중심을 노란 선으로 잇고 km(만·억, 유효 4자리)·AU(0.01AU부터)·빛으로 걸리는 시간을 창과 선 가운데(화면에 보이는 구간의 가운데, `visibleMid`)에 띄운다. 고른 천체는 레이어를 꺼도 몸체만 보인다(궤도선은 레이어대로), 사용자 화면을 끄면 선도 감춘다. 크기 비교는 따로 둔 장면(직교 카메라)에 같은 축척으로 나란히 — 북극 위·20° 앞으로 기울임·경도 0° 앞·왼쪽 앞 위에서 빛, 토성은 고리까지. 지름은 적도 지름, 포보스·데이모스·하우메아는 평균 지름. 6px 아래 천체는 동그라미. 테스트 302개 통과(`tests/tools.test.mjs` — 변이 10개 모두 실패).
최소·최대 거리(2026-11-22, 화면 승인) — 거리 창 아랫줄에 1800~2050년 중 최소·최대 거리와 날짜(작은 글씨), 「그때 위치」 스위치를 켜면 그 순간 두 천체 자리에 점·선·「지구(최소)」(몸체 없음, 겹치는 이름표는 「지구(최소·최대)」로 합침). `src/extremes.js`를 웹 워커(`extremes_worker.js`)로 돌리고 짝마다 기억 — 대부분 0.5초 안, 같은 계 위성(화성-포보스 3.5초·포보스-데이모스 5.6초)은 「계산 중…」. 다른 계는 질량중심끼리 하루 간격 → 위성·흔들림 크기 합의 2배 안 후보만 실제 위치로 둘레를 촘촘히. 지구-달 최소 1912-01-04 35만 6,394km(실제 35만 6,375km). 테스트 311개 통과(`tests/extremes.test.mjs` — 촘촘히 다 훑은 값과 대조, 변이 8개 모두 실패).
고리 셰이더 식 정리(2026-11-22) — 셰이더 식(밝기·앞뒷면·토성 그림자·고리 그림자 몫·반사율)은 `src/rings_glsl.js` 한 곳, `tests/rings_glsl.test.mjs`가 그 GLSL 문자열을 JS로 옮겨(`tests/glsl_to_js.mjs` — 모르는 문법은 멈춤) `rings.js`와 무작위 입력·고리 경계·분점 문턱(1e-6)에서 대조. 셰이더 쪽 식만 틀리게 바꾼 변이 18개 모두 실패. 텍스처를 읽는 `ringTau`만 `main.js`에 남음. 화면은 고치기 전과 같은 그림(1200×800 세 장면, 화소 차 최대 3/255 한 곳). 테스트 319개 통과.
지도 위도 기준 확인(2026-11-22) — 목성 PIA07782 설명문이 「행성 중심 위도로 같은 간격」이라 지금 방식(`ellipsoidGeometry`)과 맞음. 지도의 대적점 가운데도 남위 약 19.9°(행성 중심 위도 예상 19.6~20.0°, 측지 위도라면 22~22.5°).
혜성 코마·꼬리·핵(2026-11-22, 화면 승인) — 핵 모양: 67P Rosetta DLR SHAP4S(그대로), 핼리 Stooke(Giotto·Vega 격자 → 부피 중심), 엔케·스위프트-터틀·헤일-밥은 추정 크기에 맞춘 근사 모양(`tools/make_comets.py`, 반지름은 부피 같은 구). 활동량은 물 승화 곡선(MSY 1973) × 관측 생산율(헤일-밥만 25AU까지 일산화탄소 항). 이온 꼬리는 태양풍 400km/s 광행차 방향의 곧은 꼬리, 먼지 꼬리는 알갱이 2,400개(나이 0~120일 × β 0.01~1, R2 수열)를 (1−β)GM 케플러 운동으로 옮김(떨어질 때 상태는 1일 칸 경계 + 에르미트 보간, 밝기 × √β). 코마는 1/ρ. 따로 모은 버퍼를 1−e^(−x)로 눌러 더하고, 머리가 화면을 채우면 노출을 줄임. 테스트 338개 통과(`tests/comets.test.mjs` 12개 — 변이 11개 모두 실패).
갈릴레이 위성 지도·자세(2026-11-22, 화면 승인 전) — USGS Galileo SSI·Voyager 전구 모자이크(이오·가니메데 색, 유로파·칼리스토 흑백, `tools/make_galilean.py`). 라벨의 경도 규약이 지도마다 달라 지형으로 확인(이오 왼쪽 끝 −180°, 나머지 왼쪽 끝 0°), 극 둘레 빈 곳 3.6~4.3%는 주변 값으로 메움. 자세는 IAU 2015 + 목성계 주기 항 J3~J8 — Horizons 위치로 잰 태양 직하점 0.00002°·목성 쪽 점 0.0026°(광행차), 앱 위치로 재면 0.063°(`tests/galilean_rot.test.mjs`, 변이 8개 중 7개 실패 · J4 각속도 0.1°/세기는 0.001°라 못 가림). 화면 속 구의 태양 쪽 점이 모형과 0.001° 안(12건). 테스트 382개 통과.

## 남은 일

순서는 우선순위가 아니다. 기능 항목은 시안·계획을 승인받은 뒤 진행한다.

### 1. 지구 밤 쪽 도시 불빛과 대기 표현

- 밤 쪽 불빛: 실제 밤 지구처럼 도시 불빛만 보이게 한다. 낮 쪽 지도는 그대로 둔다. 모습은 https://www.nightearth.com 을 참고하되 그림을 옮기지 않고, 텍스처 자료는 1차 출처(NASA Black Marble 야간 조명 자료)에서 받는다. 태양 빛을 받지 않는 쪽에만 보이게 하며, 태양 방향은 Horizons 자료로 확인한다.
- 대기 표현: 지구 가장자리의 얇은 빛. 실시간으로 움직이지 않는 정적 표현이다.
- 대기 켜기·끄기: 지구에도 단다. 금성·타이탄과 같은 방식으로, 「대기 끄기」 단추를 켬/끔 스위치로 둔다.

### 2. 왜행성 세부 묘사

- 왜행성(세레스·하우메아·마케마케·에리스): 지금은 구다. 자료가 있는 것은 지도나 모양으로, 없는 것은 밝기·색 자료로 근사한다. 자료 후보는 아래 3번 표에 적었다.

### 4. 궤도 보기 기능 (신규 · 승인 전)

- 기능: 천체를 고르면 그 궤도를 보여 준다. 장반경(a)과 단반경(b)을 중심에서 선으로 그어 이름을 붙이고, 근지점·원지점에 점과 거리(km·AU)를 표시한다. 태양 주위는 근일점·원일점으로 부른다.
- 궤도 요소: **그 시각의 요소**로 그린다(결정). 행성은 Standish 요소, 위성은 맞춘 식, 왜행성·혜성은 Horizons 요소를 그 시각에 맞춘 값을 쓴다. 혜성처럼 궤도가 시간에 따라 변하는 천체도 현재 시각 기준으로 그린다.
- 진입(결정): 다른 도구(거리 재기·크기 비교)와 같은 자리, 오른쪽 아래에 둔다. 단추가 늘어나므로 도구 아이콘 하나로 압축하고, 누르면 셀렉트 형식으로 「거리 재기 · 크기 비교 · 궤도 보기」 중 고른다.
- 카메라: 중심 천체를 중심으로 궤도 전체가 화면에 들어오도록 확대·축소한다. 날아가기와 같은 방식으로 움직인다. 기본 방향은 궤도면에 수직인 위쪽(제안).
- 축척: 실제 비율을 유지한다(「결정된 것」 그대로).
- 식: a = 장반경, b = a√(1−e²), 근지점 = a(1−e), 원지점 = a(1+e).
- 확인: 값을 Horizons 등 1차 자료와 대조하는 테스트를 만들고, 변이 검사를 한다.

## 함정

- **IAU 북극 ≠ 자전 벡터.** IAU 북극은 불변면 북쪽에 있는 극이라 금성·천왕성은 자전 벡터(오른손)와 반대다. 자전축 기울기(천왕성 97.8°)는 자전 벡터로 잰다.
- Horizons 직하점은 **측지 위도**이고 경도는 순행 천체가 서경+(타이탄도), 금성·지구·천왕성·달은 동경+ — 받은 파일 머리글의 `{West-longitude positive}`를 본다. 태양에서 보면 광행시만큼 앞선 행성이다.
- 지도는 **가운데 = 경도 0°, 동쪽이 오른쪽**이어야 그대로 맞는다. **USGS 라벨의 경도 방향·가운데 경도를 믿지 말고 지형으로 확인한다**(타이탄 라벨은 서경+·가운데 180°인데 실제 배치는 왼쪽 끝 0°·동쪽이 오른쪽 · 명왕성 300m 모자이크는 태그가 가운데 0°인데 실제는 가운데 180°). 목성 PIA07782는 축 눈금이 서경(180…0…330…180)이지만 배치는 같다. 다른 규약의 원본은 `make_textures.py`에서 돌려 맞춘다.
- 구의 방향: SphereGeometry는 u=0.5가 +X, u가 커지면 −Z 쪽이다 → +X=경도 0°, −Z=동경 90°, +Y=북극(three.js로 확인함).

- 먼 천체는 투영한 z가 반올림돼 정확히 1이 된다 → 「카메라 앞인가」를 `z < 1`로 보면 이름표가 다 사라진다. 카메라 좌표의 z 부호로 본다.
- 고리 τ 질감을 GPU 자동 밉맵에 맡기면 안 된다 — τ를 그대로 평균해 간극이 메워지고, R16F는 모바일에서 자동 생성이 실패해 고리가 조용히 사라질 수 있다. 투과율로 평균한 단계를 CPU에서 넣는다.
- **JPL 위성 평균 궤도 요소표(sats/elem)는 쓰지 마라** — 주기 자릿수가 모자라고 공명 흔들림(미마스 ±43°, 70.7년)이 없어 수십 년이면 수십° 틀린다. 궤도면이 도는 주기가 자료 기간(250년)보다 긴 위성(트리톤·타이탄·이아페투스·칼리스토)은 FFT로 안 잡혀 `fit_complex`에서 낮은 주파수를 직접 훑는다.
- Horizons 트리톤 자료는 1800-01-02부터, 카론(명왕성 중심)은 01-04부터다(`fetch_moons.py` 첫 구간을 늦춤). `fit_moons.py` 전체가 약 37분 걸린다.
- **Horizons의 3축 타원체 천체(포보스·데이모스) 위도**는 「중심 방향 광선이 3축 타원체와 만나는 점의, 회전 타원체(a,a,c) 기준 측지 위도(고도 포함)」다 — 경도는 중심 경도 그대로. 납작해서 반복 계산이 천천히 모인다(30번이면 0.0008° 남음). 화성 중심에서 본 값에는 화성 공전 속도의 광행차(약 0.005°)가 들어 있다.
- **지구-화성 최소 거리는 앱 안에서 2003년이 아니라 1924년이 나온다** — Standish 요소로 2003-08-27이 5,580만km(Horizons 5,576만km, 약 3.8만km 큼)라 1924-08-22(5,576만km)가 근소하게 앞선다. 계산 방법이 아니라 행성 위치 정밀도 문제.
- 해왕성은 Standish 오차가 공표값(10″)보다 크게 나온다(실측 최대 45″). 테스트 허용치는 실측의 약 2배.
- **공명 소천체(트로이·힐다)를 접촉 궤도 요소의 평균 운동으로 돌리면 수십 년 만에 무리가 흩어진다** — 접촉 a가 공명 둘레로 흔들려 평균 운동이 최대 7~9% 다르다. 목성 평균 운동(트로이 1배·힐다 3/2배)으로 돌린다.
- Horizons 혜성은 `DES=1P; CAP;`처럼 지금에 가장 가까운 궤도 해를 고른다. 이 해로 1800~2050년을 적분한 요소를 쓴다(핼리 1835·1910 근일점도 0.11° 안).
